How it works

Agent OS is a small server on your Mac that every agent plugs into. It doesn't replace any agent; it connects them.

How it fits together

Claude Code and Codex talk to one always-on brain server on your Mac and share its memory. Cursor isn't on the shared memory yet; Agent OS can only see and set it up. The server holds the shared memory, can take an inventory of what each agent has installed (you'll see it in the first screen), and can set up each agent for a project. You drive setup from the command line for now; the first screen will come next.

How “where we left off” travels

At the end of a session, /handoff saves one short note: the next step and the last decision. The next session, in Claude Code or Codex, gets that note automatically at the start, with any secrets masked. (The dashed breadcrumb step is built but not switched on yet.)

Rules we build by

  • Connect, don't replace. Every agent still works on its own; Agent OS is a layer, never a requirement.
  • Local first. It runs on your Mac and only answers callers on your Mac.
  • Don't break your setup. Every config change is backed up first and records how to undo it (if that record fails, it tells you).
  • Secrets never leak out. One masking checkpoint on every way out.
  • One record of where we are. Docs and agents read the same note, so they can't drift apart.

Built with

Bun (runtime) · SQLite (local database) · Hono (web server) · MCP (the standard plug agents use to call tools) · launchd (keeps the server running). The first screen will likely use React with Tailwind and shadcn.
