Glossary

Plain meanings for the jargon, plus a decoder for the IDs the agents use.

Words

WordMeaning
Agent / harnessAn AI coding tool you run: Claude Code, Codex, Cursor, Hermes and others. Agent OS connects them and never rebuilds them.
Brain serverThe small always-on program on your Mac that every agent talks to. It holds the shared memory.
HandoffThe single “where we left off” note per project: the next step and the last decision. Written by /handoff; read automatically by the next session.
BreadcrumbsThe automatic trail of what each session did, meant to survive crashes. Built but not switched on yet; today only a “session ended cleanly” marker is saved.
The BrainThe full shared-memory system: wiki, deep archive and the loop that keeps it clean. Designed, not built. Today's handoffs are its first piece.
SubstrateThe agents' word for the foundation: the local server, the database and the tools agents call.
MCP“USB-C for agents”: the standard plug agents use to call tools. The brain server is an MCP server, so any agent can use it.
HookA small script an agent runs automatically at moments like session start or end. That's how memory gets saved and loaded without you doing anything.
Provisioning / blueprintSetting up each agent for a project from one file (the blueprint) that says which agent plays which role, on which model, with which files.
InventoryThe list of skills, tool servers and plugins installed across your agents. Codex skills aren't scanned yet. Built; first visible in the first screen.
Secret maskingThe one checkpoint every read passes through; anything marked secret comes out as [redacted].
MVPMinimum viable product: the smallest version that's actually useful day to day.
DogfoodingUsing Agent OS on real work to find what breaks.
Codex gateBefore a pull request opens, Codex reviews the change adversarially, trying to break it.

ID decoder

The agent docs use short IDs. If one shows up and it's not explained, it's a bug. Here's what they mean.

Looks likeWhat it is
U11A unit: one piece of the build plan. Full list below.
decision #67A row in DECISIONS.md, the log of every decision and why.
PR #69A pull request on GitHub. Careful: PR numbers and decision numbers overlap. Check which one is meant.
VS6A verification scenario: a check that proves something works for real, not just in tests.
KTD4, R7, AE1Inside a plan: key technical decision, requirement, acceptance example.
slice 1 / v0.1The Foundation milestone. “v1.1” in older docs means the Brain milestone.
